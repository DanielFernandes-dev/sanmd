and is read by Kilo (agentic CLI) and by any human contributor.

## State management

| Segment         | Source file        | Description                          |
|-----------------|--------------------|--------------------------------------|
| Game state      | `js/state.js`      | All persistent and transient state   |
| Scene state     | `js/scene.js`      | Per-scene flags, character display   |
| Dialogue state  | `js/dialogue.js`   | Line index, typing, monologue phase  |
| Phone state     | `js/phone.js`      | Screen, reset timers, message queue  |
| Gallery state   | `js/gallery.js`    | Photo selection, preview, flash    |
| Text input      | `js/text-entry.js` | Buffer, cursor, layout, shift       |
| Inventory        | `js/bag.js`        | Items, search,.pagination           |

## Persistence contract (summary)

- **Save format**: JSON with `saveVersion: 1`, stored in `localStorage` under
  key `sanmd:saves` (or in-memory when `storage` is null).
- **Manual saves**: max 9, used by Gallery photo system.
- **Autosave**: single slot, overwritten on each `registrarAutosave()` call.
- **Snapshot validation**: `persistence.js` validates structure, location,
  dialogue phase, file visibility, message state, phone state, and inventory
  before restoring. See [docs/SAVE_SYSTEM.md](docs/SAVE_SYSTEM.md) for the
  full contract.

## Testing

- **Runner**: `node --test` (no Jest, no framework — uses Node's built-in
  test runner).
- **Test files**: `test/*.test.js` plus the helper `test/load-game.cjs`.
- **DOM simulation**: Each test imports the game module via
  `load-game.cjs`, which sets up a minimal DOM (`index.html` content) and
  mocks `window`, `Audio`, `Image`, `matchMedia`, etc.
- **Coverage scope**: navigation, state transitions, saves, cutscenes,
  photo/gallery layout, keyboard, text input, title menu, scene transitions.
- **What tests do NOT cover**: real visual rendering, audio playback,
  touch events on mobile, animation timing in a real browser. Manual QA is
  required for those.

Run the full suite:

```bash
npm test
```

## Android / Capacitor

- The web assets are the source of truth. `npm run apk` copies `index.html`,
  `styles.css`, `js/`, and `assets/` into `www/`, syncs Capacitor, and runs
  `./gradlew assembleDebug`.
- The Android project (`./android/`) is generated by Capacitor — do not edit
  source files inside it manually unless debugging native configuration.
- Native `MainActivity.java` configures audio autoplay permissions for the
  Capacitor WebView.

## Kilo-specific commands

Kilo commands are stored in `.kilo/command/` as Markdown files. To add a new

current architecture.

## Common tasks

### Adding a new cutscene

1. Define the sequence (frames, timing key, steps, sounds, assets) in
   `js/data.js` as a new entry in `CUTSCENES`.
2. Ensure `CONFIG.cutscene` has a matching timing block if you use a custom
   one.
3. Use `game.services.iniciarCutscene('your_id', onComplete)` to trigger it.

### Adding a new hotspot type

1. Register the strategy in `mechanics.js` → `criarMecanicasHotspot`.
2. Return `false` if the interaction should be blocked; perform mutations if it
   should proceed.
3. See [docs/MECHANICS_PATTERN.md](docs/MECHANICS_PATTERN.md) for the contract.

### Adding a new phone app

1. Add the screen markup in `index.html` under `#phone-screen`.
2. Add a button in the home screen grid.
3. Implement the app's behavior in `phone.js` or a new `app-*.js` module.
4. Register navigation in `events.js`.

### Changing a timing value

Edit `CONFIG` in `js/config.js`. CSS variables for animations are set
programmatically via `configurarAnimacoes()`. See
[docs/MECHANICS_PATTERN.md](docs/MECHANICS_PATTERN.md) §Contrato visual.
